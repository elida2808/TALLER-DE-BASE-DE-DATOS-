Topología del Servidor y Despliegue de Réplicas

Estrategia de Creador de Transacciones y Lectura

Para tolerar picos de concurrencia de miles de jugadores simultáneos, se desacopló el procesamiento:

  • Nodo Primario (Master): Exclusivo para operaciones DML intensivas de escritura (actualización de experiencia, compras en tienda, registros).
  • Nodos Secundarios (Read Replicas): Destinados exclusivamente a la consulta de tablas de clasificación (*leaderboards*), perfiles e inventarios.

Matriz de Permisos y Perfiles Técnicos

Aplicación rigurosa del Modelo RBAC (*Role-Based Access Control*) para el personal técnico:

  • role_dba: Control total sobre objetos, gestión de esquemas, respaldos y usuarios.
  • role_soporte_sa: Permisos de monitoreo, lectura de logs y terminación de hilos bloqueados (`KILL PROCESS`).
  • role_analista_da: Acceso restringido de solo lectura (`SELECT`) a vistas anonimizadas de partidas para analítica.

Scripting de Seguridad y Creación de Usuarios

Configuración de Roles y Usuarios Granulares

Comandos SQL utilizados para la asignación restringida de privilegios:

-- Creación de roles
CREATE ROLE 'role_analista', 'role_backend_service';

-- Asignación de privilegios
GRANT SELECT ON juego_db.vw_estadisticas TO 'role_analista';
GRANT SELECT, INSERT, UPDATE ON juego_db.jugadores TO 'role_backend_service';

-- Asignación de rol a usuario de aplicación
CREATE USER 'app_api'@'10.0.0.%' IDENTIFIED BY 'PasswordSegura#2026';
GRANT 'role_backend_service' TO 'app_api'@'10.0.0.%';
SET DEFAULT ROLE 'role_backend_service' TO 'app_api'@'10.0.0.%';

Monitoreo de Estado de Replicación

Verificación de la sincronización asíncrona basada en Binary Logs (`binlog`)

-- Ejecutado en el servidor Primario
SHOW MASTER STATUS;

-- Ejecutado en el servidor Réplica
SHOW SLAVE STATUS\G
-- Verificación clave:
-- Slave_IO_Running: Yes
-- Slave_SQL_Running: Yes
-- Seconds_Behind_Master: 0
