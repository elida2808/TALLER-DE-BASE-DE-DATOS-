Estrategia de Continuidad del Negocio y Auditoría

Auditoría Transaccional Automática

Garantiza la trazabilidad total de acciones sensibles (transferencias de divisas, eliminación de ítems valiosos) mediante disparadores (triggers):

  • Guarda el estado previo (OLD) y posterior (NEW) de la transacción.
  • Registra la IP del cliente, el usuario de base de datos y la marca temporal exacta.

Estrategia Point-In-Time Recovery (PITR)

Restauración exacta de la base de datos al segundo justo antes de sufrir un ataque o falla crítica:

  • Full Backup Semanal: Copia física completa mediante mysqldump / Percona XtraBackup.
  • Binary Logs (binlog): Guardado incremental constante de todos los eventos DML para replay en caliente.

Triggers de Auditoría y Comandos de Recuperación

Trigger de Auditoría de Moneda Digital

Registra cualquier modificación en el balance de monedas de un jugador:

DELIMITER //
CREATE TRIGGER trg_auditoria_monedas
AFTER UPDATE ON jugadores
FOR EACH ROW
BEGIN
    IF OLD.monedas <> NEW.monedas THEN
        INSERT INTO log_auditoria_monedas (
            jugador_id, saldo_anterior, saldo_nuevo, usuario_bd, fecha_evento
        ) VALUES (
            OLD.jugador_id, OLD.monedas, NEW.monedas, USER(), NOW()
        );
    END IF;
END //
DELIMITER ;

Comandos de Restauración PITR ante Desastre

Secuencia ejecutada desde la consola del sistema operativo para aplicar el plan DRP:

# 1. Restaurar el backup completo inicial
mysql -u root -p juego_db < backup_full_domingo.sql

# 2. Aplicar logs binarios hasta el segundo exacto previo a la falla
mysqlbinlog --stop-datetime="2026-10-03 14:29:59" \
  /var/lib/mysql/binlog.000012 | mysql -u root -p juego_db
