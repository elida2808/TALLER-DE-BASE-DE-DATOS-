Estrategias para Eventos de Alto Tráfico

Alteración de Esquema Online (Zero-Downtime)

Durante eventos globales del juego (ej. lanzamiento de pases de batalla), es inviable bloquear las tablas. Se utilizó el algoritmo instantáneo de InnoDB:

  • ALGORITHM=INSTANT: Aplica cambios solo en metadatos sin rehacer la tabla física.
  • LOCK=NONE: Permite operaciones concurrentes de INSERT, UPDATE y DELETE mientras se modifica la estructura.

Prevención de Condiciones de Carrera (Race Conditions)

En compras de ítems con stock estricto o reclamo de recompensas únicas, la lectura simple causa inconsistencias:

  • Bloqueo Pesimista (FOR UPDATE): Bloquea la fila seleccionada hasta que la transacción actual finalice (COMMIT o ROLLBACK).
  • Nivel de Aislamiento REPEATABLE READ: Garantiza lecturas consistentes sin lecturas fantasma dentro del flujo transaccional.

Implementación Técnica en SQL

DDL Instantáneo en Producción

Añadiendo atributos de eventos sin interrumpir a los jugadores conectados:

-- Alteración instantánea sin bloqueo
ALTER TABLE jugadores 
ADD COLUMN pase_batalla_activo TINYINT(1) DEFAULT 0,
ALGORITHM=INSTANT, 
LOCK=NONE;

Transacción Segura de Compra con Cerrojo Explícito

Garantiza que el stock no sea sobrevendido ante solicitudes simultáneas:

START TRANSACTION;

-- Bloqueo explícito de la fila del ítem
SELECT stock, precio FROM tienda_items 
WHERE item_id = 104 FOR UPDATE;

-- Modificación segura tras verificar stock
UPDATE tienda_items SET stock = stock - 1 WHERE item_id = 104;
UPDATE jugadores SET monedas = monedas - 500 WHERE jugador_id = 88;

COMMIT;
