Fundamentos Arquitectónicos del Sistema

Normalización y Tercera Forma Normal (3FN)

Para asegurar el correcto rendimiento en un entorno multijugador con alta frecuencia de lectura y escritura, el esquema fue normalizado hasta 3FN:

  • 1FN: Eliminación de atributos multivalor (ej. inventarios serializados guardados como texto en la tabla del jugador).
  • 2FN: Eliminación de dependencias parciales; cada atributo no clave depende completamente de la llave primaria.
  • 3FN: Desacople de atributos transitivos, separando estadísticas globales de los perfiles individuales.

Estrategia de Llaves y Tipado Estricto

Se implementaron identificadores numéricos de alta eficiencia para garantizar búsquedas veloces en memoria RAM[cite: 2]:

  • BIGINT UNSIGNED AUTO_INCREMENT para claves primarias en tablas transaccionales de alto tráfico (partidas, historial_compras).
  • CHAR(36) UUID para identificadores de cuenta expuestos a la API externa para evitar la enumeración de usuarios.
  • DECIMAL(10,2) para el manejo estricto de la moneda digital en el juego (monedas de oro/gemas).

Scripts DDL y Carga Inicial de Datos (DML)

Script DDL Base (Estructura de Tablas)

Declaración de tablas núcleo respetando relaciones de 1:N y N:M mediante tablas intermedias:

CREATE TABLE jugadores (
    jugador_id INT AUTO_INCREMENT PRIMARY KEY,
    nickname VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    nivel INT DEFAULT 1,
    fecha_registro TIMESTAMP DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE inventario (
    inventario_id BIGINT AUTO_INCREMENT PRIMARY KEY,
    jugador_id INT NOT NULL,
    item_id INT NOT NULL,
    cantidad INT DEFAULT 1,
    FOREIGN KEY (jugador_id) REFERENCES jugadores(jugador_id) ON DELETE CASCADE
) ENGINE=InnoDB;
