Protección de la Capa de Datos

Encapsulamiento y Neutralización de SQLi

Las aplicaciones cliente no tienen acceso directo a las tablas. Toda interacción se realiza a través de procedimientos almacenados paramétricos:

  • Eliminación total del armado dinámico de cadenas SQL en el backend.
  • Parametrización estricta de tipos de datos de entrada.
  • Manejo centralizado de excepciones con declaraciones SIGNAL SQLSTATE.

Restricciones del Motor (CHECK Constraints)

Reglas de negocio integradas a nivel de motor de BD para evitar que exploits en el cliente inyecten valores incoherentes:

  • Impedir valores negativos en la experiencia, oro o nivel del jugador[cite: 2].
  • Validar rangos lógicos de atributos (ej. porcentaje de precisión entre 0 y 100%).

Implementación de Lógica Anti-Trampas

Procedimiento Almacenado de Recompensa Validada

Lógica que detecta e ignora incrementos imposibles de experiencia:

DELIMITER //
CREATE PROCEDURE sp_otorgar_experiencia(
    IN p_jugador_id INT,
    IN p_exp_ganada INT
)
BEGIN
    -- Regla Anti-Cheat: Ninguna partida otorga > 5000 XP
    IF p_exp_ganada > 5000 OR p_exp_ganada <= 0 THEN
        SIGNAL SQLSTATE '45000' 
        SET MESSAGE_TEXT = 'Alerta Anti-Cheat: Inyección de XP anómala detectada';
    ELSE
        UPDATE jugadores 
        SET experiencia = experiencia + p_exp_ganada 
        WHERE jugador_id = p_jugador_id;
    END IF;
END //
DELIMITER ;

Tabla con Validaciones Semánticas

Asegurando integridad lógica frente a manipulaciones de memoria externa:

CREATE TABLE estadisticas_jugador (
    jugador_id INT PRIMARY KEY,
    partidas_jugadas INT DEFAULT 0 CHECK (partidas_jugadas >= 0),
    victorias INT DEFAULT 0 CHECK (victorias >= 0),
    ratio_bajas_muertes DECIMAL(5,2) CHECK (ratio_bajas_muertes >= 0.00),
    CONSTRAINT chk_victorias_coherentes CHECK (victorias <= partidas_jugadas)
) ENGINE=InnoDB;
