Estrategias de Escalamiento y Rendimiento

Particionamiento Horizontal por LIST/RANGE

Distribuir millones de registros de partidas en particiones físicas independientes según la ubicación geográfica del servidor:

  • Partition Pruning: La consulta ignora particiones irrelevantes, reduciendo drásticamente la lectura de disco.
  • Separación por código de región: América (1), Europa (2), Asia (3).

Optimización de Consultas mediante Indexación

Estrategias avanzadas de índices para acelerar el matchmaking y los listados de clasificación:

  • Índices Compuestos: (region_id, rango_mmr) para búsquedas de partidas equilibradas.
  • Análisis de Planes de Ejecución: Medición mediante EXPLAIN ANALYZE reduciendo el costo de ejecución de consultas masivas.

Código SQL y Carga ETL de Datos

Creación de Tabla Particionada

Definición del esquema con particionamiento por lista de regiones:

CREATE TABLE partidas_historial (
    partida_id BIGINT NOT NULL,
    region_id INT NOT NULL,
    jugador_id INT NOT NULL,
    fecha_partida DATETIME NOT NULL,
    PRIMARY KEY (partida_id, region_id)
) ENGINE=InnoDB
PARTITION BY LIST(region_id) (
    PARTITION p_america VALUES IN (1),
    PARTITION p_europa VALUES IN (2),
    PARTITION p_asia VALUES IN (3)
);

Pipeline ETL de Carga Masiva de Datos

Comando optimizado para la ingesta rápida de logs históricos:

-- Importación acelerada deshabilitando verificaciones temporales
SET FOREIGN_KEY_CHECKS = 0;
SET UNIQUE_CHECKS = 0;

LOAD DATA INFILE '/var/lib/mysql-files/partidas_logs.csv'
INTO TABLE partidas_historial
FIELDS TERMINATED BY ',' 
LINES TERMINATED BY '\n'
IGNORE 1 LINES;

SET FOREIGN_KEY_CHECKS = 1;
SET UNIQUE_CHECKS = 1;
